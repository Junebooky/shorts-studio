# Saved-project render-only retry (A02)
Stacked follow-up to frozen runtime gate #40. Use `npx tsx scripts/quality-retry.ts PROJECT_ID REVISION` for a saved, complete QuickCreate project after a render or output-verification failure. No text or voice provider call, no project save, no revision increment, no approval. Requires current saved revision, matched timing, valid storyboard and existing audio/assets. Refuses incomplete script/voice/board failures; use the appropriate creation/alignment workflow instead.
 
Server contract: `retrySavedDraft(id,revision,progress?,signal?)` returns {projectId,revision,file,quality,source:{projectHash,audioHash},approval:'unreviewed_draft'}. Outputs a unique full-size MP4 in out/ID/retry-drafts, never replaces the ordinary final/review path. Per-project retry lease rejects concurrent retry; per-output atomic publication and decode gate come from #40. Verify project snapshot, actual narration bytes and registered assets before rendering, before publication, and after independent final QA. Source drift rejects result and removes its own new artifact when possible. Cancellation is supported at the local CLI, not shared API. No automatic retry, no paid calls, no subjective approval. This is not an immutable source snapshot or a transactional lock across shared project writes; source changes between checks or transient changes can escape detection. Shared job serialization and authenticated current-download verification remain A01 responsibilities. If process dies a retry.lock or per-output lock may remain; inspect and confirm no active process before manual recovery.
 
Actual fixture uses mocked text/voice, forces initial render failure, then real Remotion render of unchanged saved project/audio. Checks only original three mock provider requests, unchanged input and canonical path sentinel, current image/MP4 hash and frame count, no approval, and real pre-publication guard rejection. No real speech, live provider or web retry button. A01 should call this service via guarded local POST with explicit project revision; expose a draft-only result and keep final approval separate. Do not send provider configuration or API keys to retry.
