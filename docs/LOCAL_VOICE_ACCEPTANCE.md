# Local Korean voice acceptance (A03)
Independent of the guided UI, Gemini and OpenAI. A small fixed Korean sample checks the actual selected ElevenLabs voice and original timestamps without spending text-model tokens. This is a local diagnostic, not full video acceptance or naturalness approval.
1. In the repository, install dependencies with npm ci; run npm run doctor. Configure ELEVENLABS_API_KEY and ELEVENLABS_VOICE_ID in ignored .env.local. Do not share keys or commit outputs.
2. Run `npx --no-install tsx scripts/local-voice-check.ts`. Default offline dry-run: only presence/format checks, zero provider calls, no project created. A configured flag is not authentication, balance or model/voice availability proof.
3. Only after choosing to incur potential provider cost, run `npx --no-install tsx scripts/local-voice-check.ts --execute --accept-provider-cost`. One TTS-with-timestamps call maximum using existing default voice model and fixed sample; no text-model or forced-alignment requests and no auto retry/fallback. CI refuses real execution. Provider charges depend on account/model even when subsequent validation fails.
4. JSON status matched means the persisted original PCM/WAV format/duration and current timeline passed checks. Open the returned project ID in the existing editor and listen to the voice; subjective approval remains false. needs-alignment retains usable audio and requires explicit existing-audio alignment (may cost credits); failed retains the script-only or partially saved draft when available. Do not automatically rerun. Check account quota and configured voice/model locally before deciding.
The local report never includes credentials, raw provider response, voice ID or raw errors. Do not publish local audio/project/report. Unit tests inject a fake HTTP response and exercise actual storage/timing code, CLI offline mode and CI live refusal. No live provider calls in CI and no claim of voice naturalness, actual Gemini or full production acceptance.
