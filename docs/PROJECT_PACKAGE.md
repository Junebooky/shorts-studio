# Project backup / restore
A01 #15. A local portable version 1 .shorts package contains the saved project JSON and exact referenced narration and all production/reference assets, with path/size/SHA-256 inventory. Format is an uncompressed binary container, not ZIP: eight ASCII bytes SHORTS01, unsigned 32-bit big endian JSON header size, UTF-8 JSON header {version,project,files}, then exact file bytes in manifest order. No external dependencies; header 8 MiB, media up to 235 MiB, total up to 244 MiB. Buffers are held in memory, so larger streaming backups are deferred. No arbitrary paths, executable files, credentials, task/approval history or rendered MP4 included; final MP4 remains independently downloadable in the final library. Hashes detect corruption, not authenticity or maliciously rebuilt packages. Basic media header validation plus existing asset verification, not a malware scanner.
Restore always creates a fresh project ID and revision, remaps audio and asset paths while preserving asset IDs, captions, style, brief, scenes and current timing source reference. Stale analysis pointing to a different audio path is discarded. No approvals or job state inherited; listen and review again. Original is unchanged, partial restore files removed on ordinary failure. Existing app version must understand the project schema; no cross-version migration promised. UI blocks unsaved or rendering changes. CLI: npx tsx scripts/package.ts export ID FILE.shorts / restore FILE.shorts. Export refuses stale saved revision; export CLI refuses overwriting existing file. Local backup may contain private voice and media; do not commit it.

The .shorts extension is ignored by Git by default. Optional undefined fields are omitted in persisted JSON; compare canonical persisted data, not undefined object properties.

A03 media-duration integration: export verifies registered assets using server-side FFprobe for audio/video, restore revalidates on save. Install FFprobe on PATH; legacy metadata discrepancy over 100ms needs re-registration. See docs/LOCAL_SETUP.md.
