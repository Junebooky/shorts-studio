# Asset and reference workflow
Add production or reference media in the existing web card, then save. Local files are under public/workspace/PROJECT/assets/UUID.ext and excluded from Git. Metadata includes kind, role, size, SHA-256, browser-read duration (media), notes and reference brief. File name is display-only. Supported image PNG/JPEG/WebP, video MP4, audio MP3/WAV. Signature validation is basic, not a full decoder or malware scan. 50MB/file, 200MB registered/project, 100 entries; removing metadata preserves original file/history, orphan cleanup not yet implemented. SVG/HTML and arbitrary fonts are not accepted until safe handling exists.
Agent request draft includes assetEvidence and referenceBrief; inspect actual local assets before using. Do not import reference media into the final output by default; reference-only IDs are rejected by placement validation. User fixed style remains authoritative. Record intended usage and provenance in notes. Reference analysis is agent-assisted, not automated.
Storyboard beat.media optional {assetId,fit:"contain"|"cover",offsetMs:0}; visual remains the semantic fallback, media replaces main graphic, video is muted and must cover scene interval. Optional top-level music {assetId,startMs,endMs,offsetMs,volume:0.12} (0–0.3); no retiming or looping. Narration is unchanged. Remove assetEvidence/referenceBrief helper fields before applying board. Audio and video durations from browser metadata are not independently probed on upload; actual render verifies decoding. Asset bytes validated on save/render/review; changed or missing file blocks export. UI and renderer share composition. Media preview on web, no advanced asset timeline yet.
