# Asset and reference workflow
Add production or reference media in the existing web card, then save. Local files are under public/workspace/PROJECT/assets/UUID.ext and excluded from Git. Metadata includes kind, role, size, SHA-256, server-probed duration (media), notes and reference brief. File name is display-only. Supported image PNG/JPEG/WebP, video MP4, audio MP3/WAV. Signature validation is basic, not a full decoder or malware scan. 50MB/file, 200MB registered/project, 100 entries; removing metadata preserves original file/history, orphan cleanup not yet implemented. SVG/HTML and arbitrary fonts are not accepted until safe handling exists.
Agent request draft includes assetEvidence and referenceBrief; inspect actual local assets before using. Do not import reference media into the final output by default; reference-only IDs are rejected by placement validation. User fixed style remains authoritative. Record intended usage and provenance in notes. Reference analysis is agent-assisted, not automated.
Storyboard beat.media optional {assetId,fit:"contain"|"cover",offsetMs:0}; visual remains the semantic fallback, media replaces main graphic, video is muted and must cover scene interval. Optional top-level music {assetId,startMs,endMs,offsetMs,volume:0.12} (0–0.3); no retiming or looping. Narration is unchanged. Remove assetEvidence/referenceBrief helper fields before applying board. Audio and video duration is measured on the server with local ffprobe; actual render still verifies decoding. Asset bytes validated on save/render/review; changed or missing file blocks export. UI and renderer share composition. Media preview on web, no advanced asset timeline yet.

The asset manager uses the existing shared components; original file metadata remains after timeline changes. New narration clears music placement (not the library) so an old music interval cannot block shorter audio. CI uses synthetic image/video/music, verifies actual MP4 and audio amplitude; no user data or copyrighted media used.

## Server media evidence and library review
MP4/WAV/MP3 uploads now require local `ffprobe` (distributed with FFmpeg; must be on PATH). The server checks container and relevant stream type and measures conservative playback duration before writing the registered file; browser-supplied duration is a legacy hint, not trusted. Probe uses a temporary local file, file-only protocol, no shell, bounded output and 10-second timeout. Temp files are removed even on failure. Save/render verification also rechecks bytes, canonical path and media duration. A 100 ms compatibility allowance for legacy metadata is not a guarantee of sample-accurate duration; re-register files with larger discrepancies. Image validation remains signature-only, not complete decoding or malware scanning. No external analysis or rights clearance is implied.
The library shows registered counts/size, production/reference filters, actual scene/music use, preview errors and editable provenance notes. Used media cannot be removed or reclassified through this panel; unused reference assets may be promoted only through explicit confirmation. Any role/notes changes must be saved and may require a new AI production request under the existing frozen-input contract. Removal preserves original files. PR CI verifies synthetic files and real media output; no user files are uploaded to GitHub.
