# Scene asset placement evidence (P1)
The current composition uses 30 FPS and ceil(ms * fps / 1000) at each scene and source offset boundary. Millisecond checks alone can admit an off-by-one source-frame overrun (e.g. 999 ms from offset 1 ms of a 1000 ms source). `placementFrameBudget` checks both milliseconds and frame count; `assetErrors` rejects video/music overruns. FPS is tied to the existing shared FPS by unit test; no schema or renderer changes, no loop or retiming. Actual source decoding remains a separate check.
`assetPlacementEvidence` exposes graphic/image/video/invalid placement status, scene interval, fit, offset, source frame budget, music and reference IDs. `graphicCuesReplaced` is an advisory when a production asset replaces the fallback graphic; it does not block existing projects. A01 may expose this in agent requests/review after contract review. It is not a rights or semantic-relevance assessment.
The dedicated stacked PR workflow generates synthetic cyan wide image, magenta reference-only image and red/blue/green source video. Actual Short composition compares contain/cover pixel coverage, validates that the 1-second source offset skips red, verifies subsequent blue/green frames, and rejects reference placement in the model. It also checks sampled frames decoded from actual H264 preview and the output stream/length. Artifact: four PNG stills, one 540x960 MP4, JSON evidence/probe. No user assets. Pixel thresholds and sampled frames are fixture-specific; do not imply pixel-perfect or subjective quality across all projects.
Run `npx tsx --test tests/assets.test.ts`; actual render requires generated files in workspace/asset-placement-fixture (workflow commands) and FFmpeg/ffprobe, then `npx tsx scripts/render-asset-placement.ts`.
