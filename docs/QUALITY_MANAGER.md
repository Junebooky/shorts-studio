# Technical QA
Review renders invoke installed Remotion CLI ffprobe via Node (no shell or external service). Check H264, 540x960 proxy or 1080x1920 final, 30fps, frame-derived duration ±150ms and AAC if narration/music exists. Representative stills must have valid PNG IHDR dimensions and in-range frame numbers; this is not full PNG pixel decoding. Required failures/not_checked block approval/final export. Old review without QA must regenerate. UI displays actual review report and current run-bound frame gallery. Human/agent must separately inspect Korean readability, motion/audio sync, visual quality and facts; no automatic quality claim. Final render has independent technical gate and local final-quality.json. CI synthetic approvals are gate tests only. No user media uploaded.

## Sampled critical-text layout QA (A02, first increment)
The still renderer bundles a QA-only wrapper around the existing Short component. After font loading, it measures actual browser text Range rectangles for visible data-critical elements and rectangular overflow ancestor bounds; no OCR or text content is persisted. Each sidecar is bound to its PNG SHA-256 and frame index. QualityReport.layout is optional for old reports, holds sampled/missing frames and structured findings (unsafe/clipped/overlap/missing). Existing technical approval requirements are unchanged while this detector is being validated; candidate failures must be reviewed manually. Missing evidence does not pass. Only sampled frames and marked text are covered: this is not full playback, pixel occlusion, glyph clipping, SVG text, unmarked details, contrast or subjective art quality. The project SAFE values are used, not a guarantee about social platform overlays. Final MP4 continues independent stream QA. Do not treat a geometry pass as approval.

## Review comparison
Save the current run's JSON in QualityPanel, then import it after a later review. Compare only matching project and mode, distinct run IDs, and common successfully measured frame numbers. Group candidate differences by frame, code and sorted roles, preserving multiplicity. A candidate absent in the new measurement is "no longer detected", not proof of a fix (scene contents or timing may change). Unmeasured frames are explicitly excluded. Imported reports are local user-supplied data, not authenticated or approval evidence. No auto approval or persistent history; no changes to shared API.
## Render output safety / cancellation contract
`render(project, progress?, scale?, signal?: AbortSignal)` holds an exclusive output-path lock, writes to a unique sibling .partial.mp4, then renames nonempty completed output to the established destination. On failure/cancel previous MP4 remains and temporary output/lock is cleaned. A signal cancels renderMedia via Remotion makeCancelSignal, with checkpoints after bundling and composition selection. Rename is the publication commit point; too-late cancellation cannot undo it. `stills(project, outputDir?, signal?)` checks at boundaries between sampled frames; it cannot interrupt an individual still yet, and does not make a whole review atomic. Crash may leave lock/partial files: verify no process owns the lock, then manually remove orphan .render.lock and .partial.mp4 files only. Never remove an active lock. No restart persistence or UI cancel route yet. A01 must coordinate shared API job/controller and review/final signal threading, avoid publishing approvals on canceled jobs, and guard concurrent review/draft/final jobs for the same project. No change to approval policy; existing independent technical probe remains necessary.

## Final output integrity (A02 increment 3)
Full-size renders now require technical metadata AND complete decoded-frame scan using bundled ffprobe -count_frames before replacing the destination. Final production QA independently decodes again, verifies the decoded video frame count against frames(project), and records bytes/SHA-256/decodedFrames in the optional QualityReport.integrity field. Decode exceptions, timeout, diagnostic stderr or missing decoded counts are required not_checked and block success; count mismatch is fail. The output's SHA is compared before/after decode. Video and present audio streams must have decoded frame counts, not subjective audio quality or exact A/V sync. Runtime cost increases, with a five-minute decode timeout per invocation. Preview remains metadata + representative geometry. The archive/download layer is A01-owned and should bind its hash to final QA evidence, not rely on integrity presence alone.
## Interrupted output recovery
New output locks contain local PID, hostname, timestamp, and the exact random sibling temporary filename. Inspect only:
`npx tsx scripts/quality-recover.ts PROJECT_ID REVISION preview|final`
After stopping the local server/CLI and verifying all child renderer/FFmpeg processes are stopped, explicitly apply:
`npx tsx scripts/quality-recover.ts PROJECT_ID REVISION preview|final --apply --offline-confirmed`
Only a verified same-host dead PID with a safe temporary basename may be recovered. Live or reused PIDs, foreign host, malformed/legacy lock or unavailable PID status are refused. Serialized recovery removes just that recorded partial and lock; previous MP4 is retained (existence is not a quality certification). A crash during recovery may leave the recovery guard; manual offline inspection required. No automatic stale lock deletion, no cross-host/NFS guarantee, no process restart/resume, no persistent web job state. This supersedes the old manual lock removal recommendation for structured leases.

## Mobile text readability candidates (A02 increment 4)
The same sampled browser/PNG-bound sidecar now records computed CSS font size and opaque RGB foreground/background for visible marked HTML text. Contrast uses relative sRGB luminance and a conservative 4.5:1 advisory threshold for all text. Size is nominal CSS font size scaled from 1080 to a hypothetical 360 CSS-pixel video width (12px advisory floor); this is a chosen project heuristic, not a device guarantee or formal accessibility conformance. Only the element's own opaque solid background is measured; transparent/gradient, mixed children, opacity/filter/blend/text shadow are unknown, not passed. CSS transforms or zoom make size unknown; no glyph raster analysis, occlusion detection or viewing-distance assumptions. The optional readability report stores per-frame candidates and missing evidence; QualityPanel links actual review stills. Missing evidence or no measured items cannot yield pass; findings are optional and do not change technical/subjective approval rules. Synthetic good/low/gradient fixture and actual demo captions verify the measurement path in dedicated CI. No private text persisted by the sidecar. Existing review comparison remains geometry-only; status transitions show readability check changes.

## Scene-level evidence (A02 increment 5)
The representative frame plan now uses actual half-open Remotion scene frame intervals: scene start, midpoint, final visible frame, and caption start/midpoint when visible. The same deterministic plan is shared by still rendering and QA, with de-duplication. SceneEvidence aggregates expected/available/missing frames, layout and readability candidates, and unknown CSS observations. A missing planned frame cannot become a clean sample. A scene with candidates remains a candidate even if other evidence is missing; otherwise incomplete coverage is separate from no_candidate_in_sample. This is not a full-motion, pixel composition, or subjective visual-quality pass. The panel filters by attention and links only actual available stills; old reports can omit scene evidence. No additional mandatory visual approval criteria. Sampling cost increases with scene/caption count.
