# Verified MP4 transfer (A02)
Stacked follow-up from frozen #42 e5abae5, no shared API/library changes. Use server/quality/verified-download.ts in the existing local API only with trusted server-selected file and persisted/job-owned quality report (never client-supplied path or report). Final report must have all required checks passing, one required decode pass, positive decoded count and integrity SHA-256/bytes. Optional archive manifest must match that digest. Legacy reports without integrity are rejected by this helper; do not silently re-label legacy archives as newly checked.
 
`await sendVerifiedMp4(res,file,quality,{download:true,manifest?,beforeSend?})` takes a private temporary file snapshot, hashes the exact bytes copied, verifies the snapshot before HTTP success headers, and streams that copy rather than reopening the mutable original. `beforeSend` is the shared caller's latest revision/authorization/source guard after snapshot preparation. For preview use download:false. Pre-header errors propagate to existing API JSON handler; after headers fail by closing the connection and return false. No byte-range handling; full response only. Verify authorization and draft/approved distinction outside helper. Historical final archive may remain valid for its recorded revision; don't apply current-revision draft policy blindly. At archive creation, A01 should compare copied manifest digest against required QA integrity before publishing. At quick job completion retain trusted quality and revision with file; at download revalidate current draft revision in callback, not just job ID. This module does not itself change production routes or approvals.
 
Default safety limits chosen for local app: 512 MiB per snapshot, two simultaneous snapshots per process. Uses bounded streaming, private OS temp directory, cleans up on success, failure, disconnect or explicit disposal; abrupt process death may leave a temporary directory requiring offline cleanup. Additional disk space and full-file copy/hash work per transfer. Not protection against a malicious local process with same OS user access, not authenticated historical evidence, no distributed concurrency limit. `prepareVerifiedDownload` callers must send once or dispose, never call dispose during a transfer. Linux CI only. No real API keys or natural speech.
 
Actual fixture starts a localhost HTTP server around helper, uses real rendered retry MP4, changes source after snapshot validation, and asserts exact original bytes received. Same-size modification, truncation, legacy record, mismatched archive manifest, and failing current revision callback rejected before MP4 headers. Unit tests cover abort/write failure/cleanup/cap, duplicate or missing decode records and source symlink. No production API endpoint behavior claimed until A01 connects it.
